## 목표
매일 오전 6시(KST), 무신사 의류 전체 랭킹(일간·주간·월간)을 수집해 남성/여성별로 잘 팔리는·뜨는 아이템, 핏, 실루엣,

## 수집 범위 (2026-09-25부터)
- 랭킹: **남성·여성 전체 랭킹**(섹션 199, 카테고리 000), 기간 `period=DAILY`·`WEEKLY`·`MONTHLY` (`common.PERIODS`)
- 1위부터 한 페이지(≈100위)씩 내려가며 **의류만 골라 성별마다 300개**가 모이면 멈춤 (2026-09-25 사장님 결정: "전체 랭킹 300위, 의류만, 300개 채우기")
- 의류 = 무신사 대분류 상의 001, 아우터 002, 바지 003, 원피스/스커트 100
- 제외: 뷰티 104, 신발 103, 가방 004, 모자 120, 소품 101, 속옷/홈웨어 026, 디지털/라이프 102, 키즈 106, 스포츠/레저 017(운동복 포함)
- 전체 랭킹에는 카테고리 표시가 없어서(모두 000) **상품 상세정보의 대분류로 의류인지 판별**. 비의류는 요청 1번, 의류는 2번(소재 포함). 한 번 본 상품은 다시 요청 안 함
- 급상승(201)·NEW(200)·유니섹스 구분은 쓰지 않음 (2026-09-24 사장님 결정)
- CSV의 `rank` = 무신사 전체 순위(비의류 포함), `clothing_rank` = 의류끼리 순위(1~300, 분석 가중치에 사용)
- 2026-09-24 기록은 예전 방식(카테고리별 1~200위)이라 추세 비교에서 자동으로 빠짐 (`analyze_trends.data_scope`)

## 사진 판독 (매일 자동, 2026-09-26 사장님 결정)

  6. 3~5 반복 (한 번 실행에 최대 150개, 순위 높은 순. 넘치면 다음 날 이어서)

## 순위 급상승 원인 조사 (매일, 2026-09-27 사장님 지시)
'시장 동향'의 '순위가 크게 오른 상품'(성별마다 최대 10개, 하루 약 20개)마다 **왜 올랐는지, 유입이 어디서 왔는지**를
웹·유튜브·SNS·커뮤니티로 깊게 조사해 적는다. 인기 브랜드 신상품이 원인이면 그렇게 적어도 됨. 유료 API 없이 Claude가 직접.
- **자동**: 사진 판독과 같은 10시 루틴에서 이어서 (사진 판독 → 원인 조사 → 리포트 다시 만들기 → 푸시)
- 순서:
  1. `python tools/rise_reasons.py --check` → 오늘 리포트 기간별 조사할 개수 (일간 매일, 주간 월요일, 월간 1일)
  2. `python tools/rise_reasons.py --next --period daily` → `.tmp/rise_queue.json` + 화면에 상품별 **데이터 단서**(가격·할인율 변화, 대표 사진 등록일=신상 여부, 같은 브랜드 동반 상승, 판매량 표시)와 예전 조사 기록
  3. 상품마다 조사 (아래 '조사 방법') → `.tmp/rise_batch.json` 작성
     `{"상품번호": {"causes": ["유튜브·SNS 콘텐츠"], "summary": "…", "confidence": "확인", "reason": "…", "sources": [{"title": "…", "url": "https://…"}]}}`
  4. `python tools/rise_reasons.py --merge .tmp/rise_batch.json --period daily` (형식이 틀리면 거부 → 고쳐서 다시)
  5. 주간·월간 리포트 날이면 `--period weekly` / `monthly`로 2~4 반복 (비교 대상이 지난주·지난달이라 원인 기간도 그만큼 넓게 봄)
  6. 리포트 다시 만들기 → `git add data/rise_reasons.json docs` → 커밋 → 푸시 (사진 판독 8단계와 같이 해도 됨)
- 원인 종류(`causes`, 1~3개, 큰 것 먼저): 셀럽·인플루언서 착용 / 유튜브·SNS 콘텐츠 / 신상품·리뉴얼 출시 / 협업·한정판 / 할인·프로모션 / 무신사 노출 / 브랜드 화제 / 시즌·날씨
- **확인** = 출처에서 이 상품(또는 같은 모델의 다른 색)이 직접 소개·언급된 걸 봤을 때만. 출처 1개 이상 필수.
  **추정** = 직접 증거를 못 찾음 → 설명 첫머리에 "이 상품을 직접 소개한 콘텐츠는 못 찾음"처럼 밝히고 정황(브랜드 노출·할인·시즌)으로 판단. 억지로 원인을 만들지 않음.
- 설명(`reason`)엔 날짜·조회수 같은 숫자를 넣어 "언제, 어디서, 얼마나"가 보이게. 출처는 **직접 열어 본 페이지만**.
- 한 줄 원인(`summary`, 30자 이내)은 '오늘 요약'의 '순위가 크게 오른 상품'에 그대로 나감 → 원인 종류 이름을 반복하지 말고 구체적으로 (예: "패션플래닛 협업 · 9/25 콜라보 코디 영상", "추석 빅세일 추천 영상 2편에 직접 소개"). 계기를 못 찾았으면 "뚜렷한 계기 없음 · 가을 이너 수요"처럼 솔직하게.

### 조사 방법 (2026-09-27 첫 조사에서 효과 있던 순서)
1. **먼저 그 기간의 판 전체**: 무신사 행사(뉴스 검색 "무신사 ○월 세일/기획전"), 날씨, 명절. 행사 중이면 "무신사 ○○ 빅세일 추천" 유튜브가 핵심 유입 경로.
2. **유튜브**: `python tools/web_research.py search "브랜드 상품 핵심어" --recent` → 최근 영상 목록 → `python tools/web_research.py video 영상ID 브랜드명 상품핵심어`로 설명란에 이 상품이 있는지 확인. 남성 채널(패션플래닛 `UC9vu2JsuE7g-1r9HkYkOopw`·스토커즈·오정규·옷튜브·해피가이정호 등)은 `channel`로 최근 15개를 한 번에 훑기.
3. **상품명에 협업 표시**(`[패션플래닛 X 알리스]`)가 있으면 그 유튜버 채널부터.
4. **웹 검색**(WebSearch): "브랜드 상품명 착용", "브랜드 재입고/신상", 셀럽 이름. 브랜드 공식몰 상품 페이지에 '○○ 착용' 표기가 있는 경우가 많음.
5. **커뮤니티**: 어미새 패션정보 `https://eomisae.co.kr/os` (최신 20개만 보임 — 지난 글 검색은 막힘), 에펨코리아 핫딜.
- 대부분 영상은 상품 목록을 설명란에 적지만, **고정 댓글에만 적는 채널**(옷튜브·에탄올·호패션 등)은 설명으로 확인 불가 → 확인 못 한 걸로 처리.
- `www.musinsa.com`(상품 페이지·큐레이터 링크)은 열지 않음 (수집 원칙). 검색 결과에 나온 제목만 참고.
- 조사량: 상품당 유튜브 검색 1~2번 + 의심 영상 설명 확인 + 웹 검색 1~2번. 20개면 약 30~40분.

## 문제가 생겼을 때
- **"무신사가 데이터 요청을 거부"**: 클라우드(해외 서버)에서만 막히는지 로컬 PC에서 `python tools/musinsa_fetch.py`로 확인. PC에선 되면 Windows 작업 스케줄러로 전환 제안. 상세정보 단계에서 막혔다면 받은 만큼은 저장돼 있으니 다음 날 이어서 받음.
- **"수집 결과가 비정상적으로 적음" (구조 변경)**: `https://api.musinsa.com/api2/hm/web/v5/pans/ranking?storeCode=musinsa&subPan=product`에서 섹션 번호(`"sectionId"`)와 탭 이름(`applied_tab`, `extra_info`) 재확인. 상품 필드(`items[].info`, `items[].image.rank`)가 바뀌었으면 `parse_products` 수정.
- **분류 누락이 많음**: `python tools/classify_attributes.py data/history/날짜.csv`로 확인 → `attribute_keywords.json`에 키워드 추가. 짧은 키워드는 `re:` 정규식으로 다른 단어 안에서 잡히지 않게 (예: `re:블루(?!종)`).
- **소재가 이상하게 나옴**: `product_details.py`의 `FIBERS` 목록/`main_fiber` 확인. 표기 예시와 기대값을 먼저 테스트.
- **실패 알림을 못 받음**: GitHub → 오른쪽 위 프로필 → Settings → Notifications → Actions에서 실패 알림 이메일이 켜져 있는지 확인. 실행 기록은 저장소의 Actions 탭.
