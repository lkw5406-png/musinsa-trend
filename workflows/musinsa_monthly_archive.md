# 무신사 월간 랭킹 아카이브 분석

## 목표
무신사 '랭킹 아카이브'(www.musinsa.com/ranking/archive)의 **월간 랭킹**에서 의류만 골라,
달마다 무엇이 올랐는지 · 꾸준히 오른 옷 · 계절별/시즌별 유행템 · 월별 진입 원인을 정리한
**한 장짜리 페이지**를 만든다. 매일 리포트(`musinsa_daily_report.md`)와는 별개.
- 주소(2026-09-28 사장님 결정: GitHub 링크로): **https://lkw5406-png.github.io/musinsa-trend/archive/** (`docs/archive/index.html`)
- 화면 탭 순서: 핵심 요약 · 순위 찾아보기 · 꾸준템 · 시즌 캘린더 · 월별 흐름 · 브랜드 랭킹 (순위 찾아보기를 두 번째로: 사장님 요청)
- 시즌 캘린더 탭 = 계절별 추천 TOP 5 + 카테고리별 옷 종류 분석, 두 가지만. 맨 아래 '종류별 시즌 흐름'(매년 돌아오는 옷 요약·달별 상위 4종 막대)은 사장님 요청으로 삭제 (2026-09-29)
- 순위 찾아보기 달 '전체'(2026-09-29): 그해 달마다 제목 + TOP 10, '30위까지 보기'로 펼침(한 해 360줄이 길다는 사장님 선택)
- 순위 찾아보기: 연도 → 달 → 카테고리 순서로 고름 (2026-09-28 사장님 요청). 월별 흐름 TOP 5는 브랜드를 상품명 위에 가로로
- 화면 고칠 때 주의: CSS 이름이 겹치면 엉뚱한 곳 모양이 깨짐 (예: 막대 줄 `.br`과 브랜드 글자 `.br`이 겹쳐 브랜드가 세로로 쪼개짐,
  시즌 막대 `.st`와 순위 변화 `.st`가 겹쳐 ▲숫자가 찌그러짐 — 2026-09-28). 새 이름은 겹치지 않게 길게 짓고, 고친 뒤 스크린샷 한 번 확인
- 시즌 캘린더의 색 칸 표(히트맵)는 읽기 어렵다고 해서 뺌 (2026-09-28)
- **독자는 패션 디자이너** (2026-09-28 사장님): "뭐가 팔렸나"보다 "다음 시즌 뭘 디자인할까"에 쓰이게. 표·히트맵 대신 막대·카드.
  - 시즌 캘린더 맨 위 **계절별 추천 아이템 TOP 5** (기본 = 다음 시즌): 세부 종류별 그 계절 평균 자리 수로 점수
    (가장 최근 그 계절 × 0.6 + 전체 기간 그 계절 × 0.4). 대분류마다 최소 1개·최대 2개
    (겨울 아우터는 패딩·코트가 여러 세부 종류로 쪼개져 점수가 낮게 나와서 빠지던 문제 → 대분류당 1개 보장).
    카드마다 핏·실루엣·원단·디테일·컬러 키워드(대표 상품 이름에서) + 대표 상품 사진 4장.
    Claude가 덧붙일 말은 `archive_reasons.json`의 `season_picks` → `{"A": {"겨울": "..."}}`
    - 연도 버튼: 전체 · 2024년 · 2025년 · 2026년 (데이터에 있는 해가 자동으로 생김). 연도별은 그해 그 계절 달만(**겨울 = 그해 1·2·12월**), 점수 = 평균 자리, 비교 = 전년 같은 계절
  - **카테고리별 옷 종류 분석** (2026-09-29 사장님 요청, 계절 추천 TOP 5 아래, **무신사 데이터만** — 뉴스·날씨 안 씀):
    위 계절·연도 버튼을 따라감. 대분류(상의·아우터·바지·원피스/스커트) 버튼으로 고름.
    - 종류별 자리: 대분류 TOP 30 평균 자리 막대 + 비교 세로 선, 그 종류 **세부 카테고리 TOP 30**에서 정가 중간값·범위(가운데 50%)·브랜드·디자인 특징(순위 가중)
    - 추천 옷 종류 5 (종류+디자인 조합, 예 '크롭 반소매 티셔츠'): 점수 = 종류 평균 자리 × 세부 TOP 30 안 그 특징 비율(순위 가중), 특징 비율 20% 이상, 종류당 최대 2개.
      종류 이름과 겹치는 특징은 뺌(데님 팬츠의 '데님' 등)
    - 추천 상품 5: 이 기간 대분류 TOP 30 순위 점수 합(1위 30점…30위 1점), 판매 종료 제외, 종류당 최대 2개
  - '브랜드 랭킹' 탭(예전 '키워드·브랜드'): 누적 TOP 15 막대 + 최근 6개월 뜨는 브랜드(그 전 6개월 대비, 세로 선).
    디자인 키워드 막대는 사장님 요청으로 뺌 (2026-09-28). 키워드는 추천 카드 안에만 남음

## 범위 (2026-09-28 사장님 결정)
- 기간: 아카이브 첫 달 **2024-01**부터 지난달까지 (2023-12 이전은 무신사에 없음)
- 성별: 전체(A) · 남성(M) · 여성(F)
- 카테고리: 의류 대분류 4개(상의 001 · 아우터 002 · 바지 003 · 원피스/스커트 100) + 그 아래 세부 카테고리 전부(약 45개)
  - 가방·모자는 넣었다가 같은 날 뺌. 스포츠/레저(운동복)는 매일 리포트와 같이 제외
- 달·성별·카테고리마다 TOP 30 (무신사 기준: "1개월 간의 고객 구매·활동 데이터")
- 월간 랭킹은 **매월 1일**에 지난달 것이 올라옴 (집계 전에 요청하면 "정보가 존재하지 않습니다")

## 데이터 주소 (무신사 화면이 쓰는 공개 주소, 2026-09-28 확인)
- 카테고리 목록: `https://api.musinsa.com/api2/dp/v1/ranking-archive/categories?yearMonth=202608&gf=A`
- 순위: `https://api.musinsa.com/api2/dp/v1/ranking-archive/goods?yearMonth=202608&gf=A&category=001`
- `yearMonth`는 **YYYYMM** (하이픈 넣으면 400 "잘못된 파라미터")
- 찾는 법(구조가 바뀌면): 아카이브 페이지 → `static.msscdn.net/static/v4/pc/ranking/ranking.js` → `ArchivePage.js` 안에서 `ranking-archive` 검색

## 순서와 Tool
| 단계 | Tool | 결과물 |
|---|---|---|
| 1. 수집 | `python tools/musinsa_archive.py` (이미 받은 달은 건너뜀, `--force`로 다시) | `data/archive_monthly/YYYY-MM.csv` |
| 1-2. 정가 | `python tools/archive_prices.py` (백그라운드, 이어받기) | `data/archive_prices.json` |
| 2. 분석 | `python tools/analyze_archive.py` | `.tmp/archive_analysis.json` |
| 3. 원인 조사 (Claude) | 웹 검색 · 무신사 월간 랭킹 콘텐츠 | `data/archive_reasons.json` |
| 4. 페이지 | `python tools/build_archive_report.py` | `docs/archive/index.html` |
| 5. 게시 | `git add` → `git commit` → `git pull --rebase` → `git push` (매일 자동 실행도 같은 저장소에 올리므로 먼저 pull) | 1~2분 뒤 GitHub 주소에 반영 |

- 수집 시간: 한 달에 약 3~5분(요청 약 150번, 간격 1.5초). 처음 32개월은 약 2~2.5시간 → **백그라운드로 돌림**.
  다음 달부터는 새 달 하나만 받으니 5분.
- 정가 (2026-09-29 사장님 요청: 순위 찾아보기에 정가만): 아카이브엔 가격이 없어 상품 상세(`goods-detail.musinsa.com/api2/goods/{id}`)의
  `goodsPrice.normalPrice`를 상품마다 한 번 받음. **조회한 날의 정가**(그 달 당시 가격 아님 — 무신사가 과거 가격을 주지 않음, 사장님 OK).
  대분류 TOP 30 상품(약 2,300개, 1시간) 먼저 → 세부 카테고리 상품(약 2.3만 개). 전부 약 12~13시간이라 PC 켜 둔 동안 여러 번에 나눠 이어받음.
  매일 수집 CSV의 original_price로 먼저 채워 요청을 줄임. 새 달이 추가되면 그 달 새 상품만 받으면 됨.
- 사진: GitHub 페이지는 모든 상품 사진을 무신사 작은 사진(`_125`) 주소로 바로 불러옴 (매일 리포트와 같은 방식).
- Claude 링크로 따로 만들 때만 `--embed`: 외부 사진이 막혀서 일부 상품 사진만 줄여 넣음(16MB 제한, Pillow 필요).

## 분석 기준 (analyze_archive.py)
- **꾸준템**: 대분류 TOP 30에 든 달 수 → 평균 순위 순. 최장 연속 달 수, 최고 순위 함께
- **시즌 캘린더**: 대분류 TOP 30을 세부 종류별로 셈(상품의 세부 종류 = 세부 카테고리 순위에 가장 많이 나온 곳)
- **계절 대표 아이템**(페이지에서 계산): 계절 평균 자리 수가 1년 평균의 1.3배 이상이고 3자리 이상
- **원인 조사 후보(notable)**: 지난달 대비 신규 진입 · 재진입 · 10계단 이상 상승, 성별·달마다 12개
- **키워드**: 상품명에서 핏·실루엣·원단·디테일·컬러 (`tools/attribute_keywords.json` 재사용)

## 원인 조사 (Claude가 직접, 무료 웹 검색만)
`data/archive_reasons.json` 형식:
```json
{
  "intro": "페이지 맨 위 한 줄",
  "findings": [{"title": "", "body": "", "ids": ["상품번호"], "g": "A|M|F|all"}],
  "seasons": {"봄": "", "여름": "", "가을": "", "겨울": ""},
  "categories": {"001": "상의 시즌 흐름 한 단락"},
  "months": {"2025-10": {"summary": "", "points": [""], "sources": [{"title": "", "url": ""}]}},
  "items": {"상품번호": "꾸준히 팔린 이유"},
  "month_items": {"2025-10:상품번호": "이 달에 뜬 이유"},
  "keywords_note": "", "brands_note": ""
}
```
- 먼저 볼 곳: **무신사 월간 랭킹 콘텐츠**. 무신사가 달마다 카테고리 1위 상품과 이유를 적어 둠
  - 2025-02~2025-09: "N월 월간 랭킹 리포트" (예: musinsa.com/content/1346352932807459237 = 2025년 2월)
  - 2025-10~: "월간 랭킹 : N월 판매 TOP 브랜드" (예: musinsa.com/content/1434775915269254376 = 2025년 10월)
  - 2025-01·2024년 것은 본문이 안 읽힘(cms 주소) → 뉴스 검색으로 대신
- 그다음: 날씨(기상청 월·연 기후특성), 무신사 세일 일정(무진장 여름·겨울 블프, 감사 세일, 명절), 연예인 착용·협업·캠페인 뉴스
- 이유를 못 찾으면 추측으로 채우지 말고 비워 둠 (페이지는 빈 칸을 안 보여줌). "무신사 공식 이유가 아님"은 페이지 아래에 적혀 있음

## 문제가 생기면
- `DISPLAY_000_0002 … 존재하지 않습니다` = 그 달·카테고리 랭킹 없음(정상). 대분류가 200행 미만이면 저장 안 하고 넘어감
- 401/403/429 = 무신사가 거부 → Tool이 바로 멈춤. 억지로 재시도하지 말고 사장님께 보고
- 새 PC에 Python이 없으면: `winget install --id Python.Python.3.12 -e --scope user`, 사진 줄이기용 `pip install --user Pillow`
  (2026-09-28 새 PC에서 발견)
